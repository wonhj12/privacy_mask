# 마스킹 설정·사용자 정의 설계

> 설계 시점의 결정과 그 이유를 남긴 문서다. 구현 후 코드와 다르면 코드를 믿는다.

## 목표

프롬프트를 모델에 보내기 전에 로컬에서 개인정보·비밀값을 가린다.

- 자주 나오는 개인정보·비밀값은 기본으로 가린다.
- 기본 규칙은 항목별로 켜고 끌 수 있다.
- 사용자가 키 이름과 정규식을 추가해 가릴 수 있다.
- 사용자가 지정한 구간은 가리지 않고 그대로 보낸다.

범위는 사용자가 직접 입력한 프롬프트(`prompt.submit`)까지다. Claude가 도구로 읽은 파일·명령 출력은 이번 범위가 아니다.

## 마스킹 방식

기준: **로그를 읽는 사람이 그 값이 누구 것인지 특정할 수 있어야 하는가.** 필요하면 일부 노출, 아니면 전체 가림.

모든 결과는 `[라벨#번호]`로 시작한다. 같은 값은 같은 번호, 번호는 프롬프트마다 1부터.

| 방식 | 대상 | 예 |
|---|---|---|
| 전체 가림 | 주민·외국인등록번호, 운전면허번호, 모든 비밀값, 키로 찾은 값 | `[주민번호#1]` `[JWT#1]` `[db.password#1]` |
| 일부 노출 | 전화, IP, 카드, 계좌, 사업자번호, 이메일, 사용자 정규식(`partial`) | 아래 |

일부 노출 형식:

- **관례가 있는 것은 관례를 따른다.**
  - 전화: 끝 4자리. `[전화번호#1] 010-****-5678` (유선은 지역번호 + 끝 4자리)
  - IP: 첫·끝 옥텟. `[IP#1] 10.***.***.5`
  - 카드: 끝 4자리. `[카드번호#1] ****-1111` (영수증 관례)
- **그 외는 앞 2자·뒤 2자.** 구분자(`-` `.`)는 남기고, 구분자를 뺀 글자 중 앞 `partial_keep`자·뒤 `partial_keep`자만 보인다. 글자 수가 `2 × partial_keep` 이하면 전부 `*`.
  - 계좌: `[계좌번호#1] 11*-***-****89`
  - 사업자번호: `[사업자번호#1] 12*-**-***90`
  - 이메일: 아이디 부분에만 적용하고 도메인은 그대로. `[이메일#1] ho********ng@test.co.kr`
  - 사용자 정규식 `partial: true`: 매치 전체에 적용

127.0.0.1·0.0.0.0은 IP로 보지 않는다 (기존 유지).

## 처리 순서

순서가 결과를 바꾼다. 앞 단계가 넣은 `[..#n]` 자리표시자를 뒤 단계가 건드리지 않는 것이 전제다.

1. **`###` 구간 분리.** 프롬프트를 마스킹할 조각과 건너뛸 조각으로 나눈다. 건너뛸 조각만 있으면 설정을 읽지 않고 구분자만 지워 보낸다.
2. **설정 읽기.** 오류면 전송 차단.
3. **비밀값 형식 규칙** (종류별 라벨).
4. **키 규칙.** 기본 비밀값 키 + 기본 개인정보 키 + 사용자 키를 함께 본다. 결과는 `[키이름#n]`.
5. **키로 찾은 값 전체 치환.** 같은 값이 키 없이 다른 곳에 나와도 같은 자리표시자로 바꾼다. 최소 길이는 아래 설정.
6. **개인정보 형식 규칙.** 운전면허 → 사업자번호 → 계좌 순으로 엄격한 형식부터. 주민번호·전화·이메일·카드는 기존 순서 유지. IP는 맨 끝.
7. **사용자 정규식.** 이미 넣은 `[..#n]` 안은 건너뛴다.

건너뛸 조각은 3~7단계 어디에도 들어가지 않는다. 그 안의 `key=value`는 키로 수집되지도 않는다.

## 마스킹 제외 구간 `###…###`

- `###` 바로 안쪽 양 끝이 공백·`#`이 아닌 글자여야 구분자로 본다. 안쪽 중간의 공백은 괜찮다.
  - `###password=abc123###` → 제외 구간
  - `### 제목` → 마크다운 제목 (구분자 아님)
  - `##########` → `#`이 4개 이상 이어지면 구분자 아님
- 여러 줄에 걸쳐도 된다.
- 구분자는 지우고 안쪽만 그대로 보낸다.
- 닫히지 않은 `###`은 글자로 보고 평소대로 마스킹한다.
- 제외 건수 알림은 띄우지 않는다.

## 기본 규칙

### 개인정보 형식

| id | 라벨 | 형식 | 방식 |
|---|---|---|---|
| `rrn` | 주민번호 | 기존 규칙 (월·일 검사, 외국인등록번호 포함) | 전체 |
| `driver_license` | 운전면허 | `NN-NN-NNNNNN-NN`, 앞 2자리 지역 코드 11~26·28. 2014년 이전 `지역명 NN-NNNNNN-NN`도 포함 | 전체 |
| `phone` | 전화번호 | 기존 규칙 | 일부 (끝 4) |
| `email` | 이메일 | 기존 규칙 | 일부 (아이디 앞뒤 2) |
| `card` | 카드번호 | 기존 규칙 (BIN + Luhn) | 일부 (끝 4) |
| `biz_no` | 사업자번호 | `NNN-NN-NNNNN` + 체크섬 (가중치 1,3,7,1,3,7,1,3,5) | 일부 (앞뒤 2) |
| `account` | 계좌번호 | 기존 규칙. 운전면허·사업자번호에 걸리지 않은 것만 | 일부 (앞뒤 2) |
| `ip` | IP | 기존 IPv4 규칙 | 일부 (첫·끝 옥텟) |

라벨을 틀려도(사업자번호를 계좌로) 둘 다 가려지므로 새지는 않는다. 피해야 할 오탐은 가리면 안 되는 값(날짜·주문번호)을 가리는 것과 가려야 할 값을 놓치는 것이다.

### 개인정보 키 (전부 `[키이름#n]` 전체 가림)

키 비교는 대소문자·`_`·`-`를 무시한다. 기술 용어와 겹치는 단어가 많아 **오탐 없는 쪽으로 좁게** 잡고, 놓친 키는 사용자 키로 보완한다.

| id | 잡는 키 | 거르는 것 |
|---|---|---|
| `name_key` | `cust`·`customer`·`member`·`mbr`·`buyer`·`receiver`·`recipient`·`holder`·`owner`·`emp`·`employee`·`real`·`full` + `name`/`nm`, `성명`·`이름`·`고객명` | `fileName`·`hostName`·`tableName` 등 위 접두어가 없는 `name` |
| `address_key` | `addr`·`address` (앞에 `home`·`road`·`jibun`·`detail` 등 허용), `주소` | 앞에 `ip`·`mac`·`remote`·`local`·`server`·`host`·`email`·`mail`·`bind`·`proxy`가 붙은 것 |
| `birth_key` | `birth`·`birthday`·`birthDate`·`dob`·`생년월일` | |
| `card_extra_key` | `cvc`·`cvv`·`cardExp`·`cardExpiry` | `expires_in` 같은 토큰 만료 |

`userName`은 이름으로 보지 않는다. 기존 코드가 로그인 ID 추적 용도로 일부러 제외했다. 실명을 담는 환경이면 사용자 키에 추가한다 (README에 안내).

## 설정

켜고 끄기·숫자·키 이름 목록은 플러그인 설정(`userConfig`), 정규식은 별도 JSON 파일. `userConfig`는 string·number·boolean·file과 문자열 배열(`multiple: true`)만 받고 객체 배열은 받지 않아서 나눴다.

### `userConfig`

| 키 | 타입 | 기본값 | 설명 |
|---|---|---|---|
| `enable_<id>` | boolean | `true` | 위 표의 규칙 id마다 하나 (20개) |
| `propagate_min_text` | number | `2` | 개인정보 키·사용자 키의 문자 값 전체 치환 최소 길이 |
| `propagate_min` | number | `6` | 숫자로만 된 값(`-` `.` 제외)과 비밀값 키 값의 전체 치환 최소 길이 |
| `partial_keep` | number | `2` | 일부 노출 "앞뒤 N자" 규칙의 N |
| `custom_keys` | string, multiple | `[]` | 사용자 키 이름. 개인정보 키와 같은 최소 길이 기준 |
| `patterns_file` | file | 없음 | 사용자 정규식 파일 경로. 비어 있으면 건너뜀 |

공백이 낀 값은 길이와 상관없이 전체 치환하지 않는다 (기존 유지).

### 사용자 정규식 파일

```json
[
  { "label": "사번", "regex": "EMP\\d{6}" },
  { "label": "여권번호", "regex": "[A-Z]\\d{8}", "partial": true }
]
```

- `partial`이 없거나 `false`면 전체 가림, `true`면 앞뒤 `partial_keep`자 노출.
- 엔진이 `g` 플래그를 붙인다. 빈 문자열에 매치되는 경우는 건너뛴다.
- 프롬프트마다 다시 읽는다. 고친 내용이 `/reload-plugins` 없이 반영된다.

## 오류 처리

전송을 막는 경우 (차단 메시지에는 원인만, 프롬프트 내용은 넣지 않는다):

- `patterns_file`을 지정했는데 파일이 없음
- JSON 파싱 실패, 배열이 아님, 항목에 `label`·`regex`가 없거나 문자열이 아님
- 정규식 문법 오류 (몇 번째 항목인지 표시)
- 마스킹 중 예외 (기존 유지)

이유: 사용자 정의 항목은 대개 가장 민감한 값이라, 빠진 채 보내면 바로 샌다. 설정은 고치면 되지만 나간 값은 회수할 수 없다.

알려진 한계: 매우 느린 사용자 정규식(`(a+)+$` 류)은 전송을 멈추게 할 수 있다. JavaScript 정규식에 실행 시간 제한이 없다. README에 주의 문구로 남긴다.

## 구조

```
hooks/
  register.ts   훅 연결 (구간 분리 → 설정 → 마스킹 → 전송/차단, 알림)
  rules.ts      기본 규칙 목록 (id·라벨·방식·정규식)
  config.ts     userConfig + 정규식 파일 읽기·검증
  mask.ts       엔진. 설정 객체를 받는 순수 함수
```

규칙은 `{ id, label, mode, re, apply }` 형태의 목록이다. 설정은 `id`로 켜고 끄고, 사용자 정규식도 같은 형태로 변환해 7단계에 넣는다.

알림은 기존처럼 총 건수와 라벨별 건수를 보인다.

## 테스트

- 기존 테스트는 유지하고 바뀐 출력 형식만 기대값을 고친다.
- 추가: 항목별 끄기, 운전면허·사업자·계좌 구분, `###` 구간(일부·전체·닫히지 않음·제목·장식선), 최소 길이 설정, `partial_keep`, 사용자 키, 사용자 정규식(`partial` 포함), 설정 오류 시 차단.
- 테스트 데이터는 직접 만든 값만 쓴다. 체크섬을 통과하는 사업자번호도 계산해서 만든다.

## 구현 전 확인할 것

- `register.ts`에서 같은 폴더의 다른 `.ts`를 `import`할 수 있는가. 안 되면 한 파일 안에서 구역을 나눈다.
- 테스트 도구(`claude-code/testing`)에서 `userConfig` 값을 넣을 수 있는가. 안 되면 `mask.ts`를 직접 테스트한다.
- 사업자번호 체크섬 계산식 (python-stdnum `kr/brn.py`와 대조), 운전면허 2014년 이전 지역명 표기, 웹훅·Azure·쿠키 형식.
- `userConfig` boolean 20개가 설정 화면에서 어떻게 보이는가. 너무 길면 "끌 id 목록" 하나로 바꾼다.

## 버린 대안

- **백틱(`` ` ``)으로 제외 구간 표시:** 로그를 ` ``` `로 감싸 붙여 넣는 경우가 많아, 가장 가려야 할 내용이 통째로 원문 전송된다.
- **`₩` 한 글자 구분자:** 금액 표기(`₩10,000`)가 두 번 나오면 그 사이가 원문으로 나간다. 한국어 자판 전용이라는 점도 맞지 않았다.
- **`@@` · `{{ }}` · `%%` 구분자:** diff 헝크 헤더, 템플릿 문법, Mermaid 주석·배치 변수와 겹친다.
- **일부 노출을 노출 부분만으로 (`010-****-5678`):** 끝자리가 같은 두 값을 구분할 수 없다. 자리표시자 번호와 함께 쓴다.
- **형식 비밀값을 `[비밀값#n]` 하나로:** 무슨 값이었는지 맥락이 사라진다. 값은 다 가려지므로 종류를 드러내도 새는 정보가 없다.
- **사용자 키를 비밀값용·개인정보용 두 목록으로:** 차이가 전체 치환 기준 하나뿐인데 매번 고르게 만든다.
- **설정 오류 시 기본값으로 마스킹 후 전송:** 사용자 정의 항목이 빠진 채 나간다.
- **사용자 정의를 키 이름만으로:** 키 없이 값만 나오는 사번·여권번호 같은 형식을 못 잡는다. 반대로 정규식만으로 하면 단순한 키 추가에도 정규식을 써야 한다.
- **여권번호·차량번호·MAC 등을 기본 규칙에:** 오탐이 많거나 드물다. 사용자 정규식으로 넣는다 (README에 예시).
